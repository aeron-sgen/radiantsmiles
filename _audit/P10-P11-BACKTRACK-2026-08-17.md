## P10 — Pipeline setup. WAS NEVER EXERCISED HERE. Now proved both directions.

**A wrong first reading, corrected.** The first check looked for `build.mjs`, `revision-rules.mjs`
and `rverify.mjs` inside `Code/client-sites/radiantsmiles/` and found none, which looked like a
missing-artefact gap. It is not. The blueprint's word is *"paths parameterized"*, and the shipped
design matches it:

- `build.mjs` takes `--site <client-site-root>` (or `SITE_ROOT=`), and lives once in the skill.
- `revision-rules.mjs` is a **thin loader carrying zero doctrine literals** — every tier, price,
  competitor, banned token and route rule is read from the per-client `client-rules.json`.

So the per-project artefact for radiantsmiles is `_handoff/client-rules.json` (22,949 bytes, present).
**Absence from the build tree is correct architecture, not a gap.**

**The real gap, verified:** `pages/*.html` was **0**. Two `.content.html` fragments existed
(`dental-implants`, `services`) and neither had ever been through the build. Every render gate result
recorded on this build before today was measured on a `_design/_tournament/**/_assembled/` preview,
never on build output.

### G10 (a) — clean fragment builds

```
node build.mjs --site <root>     ->  Done: 2/2.   EXIT=0
```
Both pages built: `services.html` 60,792 B, `dental-implants.html` 63,147 B. The build runs its own
render-gate stack inline and every one passed: `stat-treatment`, `section-rhythm` (1440/768/375),
`section-density`, `no-text-overlap` (375 + 1440), `mobile-quality` (375/768/1024/1200/1440),
`responsive-ladder`. The numbers agree exactly with the ones measured separately on the previews
(services §1 = 1.20vh / density 496.7 both ways), which is what proves the preview harness and the
real build see the same page.
